# Panoply 识别规则设计

把一个识别失败的标题变成一条可用的 `custom_words` 规则。核心原则：**不凭空设计规则——先用真实解析器复现，再设计，再回归验证**。规则是正则，看着对和真的对是两回事。

**交付物是规则，不是代码诊断。** 全流程唯一的实证手段是跑临时解析测试、看输出；输出即证据，足够定位失败模式并设计规则。禁止展开源码分析：不追调用链、不读 pipeline/tmdb/webui 内部实现、不查配置加载与在线服务状态。只有第 0 步判定为「解析器缺口」时，才进入 `internal/mediaparser/` 读代码。

## 第 0 步：判断该写规则还是改解析器

先跑一次**无规则**解析（见第 1 步），看失败模式：

- **个案**（特定字幕组的特殊命名、需要屏蔽的杂质词、集号偏移）→ 写识别规则，继续本流程
- **普遍缺口**（多个不同来源的标题都因同一种记法失败，如 v2.8.1 之前的 `S01E06`）→ 改解析器 `internal/mediaparser/`，走「多样本表驱动测试 + 按逻辑拆分 conventional commit」流程，不要用规则打补丁

判断标准：失败的记法换个番名/字幕组还会出现吗？会 → 解析器缺口。

## 第 1 步：实证复现

写临时测试跑真实解析器（不要靠脑内模拟正则，也不要靠读源码推理——跑测试看输出即可）：

```go
// internal/mediaparser/tmp_rule_test.go（用完删除）
func TestTmpRule(t *testing.T) {
	title := "粘贴目标标题"
	for _, words := range [][]string{nil, {"旧词 => 新词"}} { // 无规则 vs 带候选规则
		m := MetaInfo(title, "", true, words, nil)
		fmt.Printf("Cn=%q En=%q Type=%v S=%v E=%v Team=%q Pix=%q\n",
			m.CnName, m.EnName, m.Type, m.BeginSeason, m.BeginEpisode, m.ResourceTeam, m.ResourcePix)
	}
}
```

```bash
go test ./internal/mediaparser/ -run TestTmpRule -v
```

正确识别的标杆：`CnName`（或 `EnName`）能命中 TMDB 搜索、`Type=电视剧/电影`、季集号正确。只看 Name() 不够——中文库要确认 CnName 非空。

WebUI 若在运行，也可用「解析测试」弹窗（`ParseTestModal`）快速核对，但它只能用当前已保存的规则，不适合迭代候选规则。

## 第 2 步：诊断——标题走哪条路径

`MetaInfo` → `IsAnime`（internal/mediaparser/words.go）分流：

| 条件 | 路径 | 文件 |
|---|---|---|
| `[xxx]` 开头，或含 番/漫/动漫 关键词 | anitomy 动漫路径 | anitomy.go + metaanime.go |
| 其他 | 剧集路径 | metavideo.go |

各路径已支持的季集记法（截至 v2.8.1）：

| 记法 | anitomy | metavideo |
|---|---|---|
| `S01E06` / `S1E6` / `S01 E06` / `S01E06v2` / `[S01E06]` | ✅ | ✅ |
| ` - 12`（空格-空格-集号，标题尾部） | ✅ | ❌ |
| `[12]` 括号纯集号 | ✅ | 视情况 |
| `第12话/集` | ✅ | 部分 |
| `S02` / `Season 2` | ✅ | ✅ |
| `Show.Name.S01E06.720p` 点分隔 | ❌ | ✅ |

anitomy 的已知行为（改写标题形状时要利用/提防）：

- 多语名 `A / B / C / D` 收敛为 `A / D`（首尾保留，仅 `" / "` 带空格分隔；`[05/06]` 无空格斜杠只留末段）
- 标题含 ` - ` 时**跳过**上述斜杠收敛（改写出 ` - ` 会改变名称提取行为）
- `~`、`～` 等装饰符会残留在名称里

## 第 3 步：设计规则

四种格式（写入 `config/parser-rules.yaml` 的 `custom_words`，每行一条）：

```yaml
custom_words:
  - "屏蔽词"                          # 直接删除
  - "旧词 => 新词"                    # 替换（旧词按正则）
  - "前缀 <> 后缀 >> EP+1"           # 集偏移（支持 + - * / % 与括号，EP 为集数占位符）
  - "旧词 => 新词 && 前 <> 后 >> EP-1" # 组合：替换命中后才偏移
```

**词法陷阱（每条都实测踩过）：**

1. 替换词/屏蔽词按正则编译且自动加 `(?i)`。**RE2 不支持 lookahead / lookbehind / 反向引用**；含 `(?=` 的规则不报错，而是**静默退回字面量匹配**
2. 替换串支持 `\1`~`\9` 捕获组引用（v2.8.1 起 `\2+` 才正确，之前会错取第 1 组）
3. 词条两端被 TrimSpace——靠前导空格锚定开头无效
4. 规则**全局生效**于文件整理 pipeline 与 RSS 订阅两条链路，泛化规则会误伤其他标题

**设计原则：**

- **窄作用域优先**：用番名片段或字幕组做上下文锚定。例：`'Chikara S01E(\d{2})\b => Chikara S01 - \1'` ✅，裸 `'S(\d{2})E(\d{2})\b => S\1 - \2'` ❌（会改坏剧集路径所有 SxxExx 标题）
- 转写成解析器**已支持**的记法（` - 12`、`S02`、`[12]`），不要发明新记法
- 多捕获组规则注意 `\b` 边界：`S01E06E07` 连写因 `6E` 间无词边界不匹配 `S(\d{2})E(\d{2})\b`，这是已知边界不是 bug

## 第 4 步：回归验证（必做）

临时测试扩展为三组：**目标标题（无规则）→ 目标标题（带规则）→ 回归语料（带规则）**。回归语料必须覆盖：目标标题所在路径的常见记法 + 另一条路径的 SxxExx 标题。

语料清单见 [references/corpus.md](references/corpus.md)，把目标标题同类形态补进去再跑。判据：带规则后，回归语料的解析结果与不带规则**逐字段一致**（或差异明确是修复而非破坏）。

## 第 5 步：落地

写入 `config/parser-rules.yaml`（该文件不受 git 跟踪，是本机运行配置）：

```yaml
custom_words:
    - \{[^}]*}=>
    # 注释写清适用场景与回归验证日期
    - 'Chikara S01E(\d{2})\b => Chikara S01 - \1'
```

- 含空格/括号/反斜杠的词条用**单引号**包裹，避免 YAML 转义歧义
- 每条规则配一行注释说明针对哪类标题
- 删除临时测试文件，跑 `go test ./internal/mediaparser/ -count=1` 确认干净

## 案例存档

- 多语名 + SxxExx（`[Nix-Raws] 装备我最强 / 裝備我最強 / テムパル～… / Tempal Item no Chikara S01E06 [CR WEB-DL …]`）：v2.8.1 起解析器原生支持，**零规则**即可识别——先复现确认是否真的还需要规则
- 罗马音转写名（`[Anti-DEI] Hitozukiai ga Nigate na … Yubiwa - 01 […]`）：季集解析正常，但罗马音名与 TMDB 官方登记名对不上。规则=**全名替换为 TMDB 官方中文名**（`'罗马音全名 => 官方中文名'`），全名做锚零误伤，CnName 直接命中搜索（2026-11-02）
